# 05 任务卡与提示词

## 一、任务卡

每类文本模型调用是一张任务卡，放在 `src/tasks/<任务>.ts`：

```ts
interface TaskCard<Out> {
  name: string                          // 「定妆描述」
  prompt: string                        // config/prompts/tasks/portrait-desc.md
  context(db: Store, scope: Scope): Context        // 按清单取上游产物
  output: 'json' | 'text'
  schema?: ZodType<Out>                 // json 输出的结构
  checks(out: Out, ctx: Context): Problem[]        // 程序能确定的检查
  save(db: Store, scope: Scope, out: Out, ctx: Context): Artifact
}

interface Context {
  inputs: ArtifactRef[]                 // 读到的上游产物（具体版本），用于 edge 和 input_digest
  sections: { title: string; body: string }[]      // 拼成用户消息的各段
}
```

### 一次调用的过程

```mermaid
sequenceDiagram
  participant SC as 调度器
  participant R as tasks/runner
  participant PR as tasks/prompt
  participant DB as 产物库
  participant M as 文本模型
  SC->>R: run(card, scope, {previous?, instruction?})
  R->>DB: card.context(scope)
  R->>PR: assemble(card.prompt, project.style, project.genre)
  PR-->>R: system 文本、prompt_version
  R->>R: 拼用户消息；估算长度，超过 8k token 报警并记录各段大小
  loop 最多 3 次（首次 + 2 次重写）
    R->>M: system + user
    M-->>R: 输出
    R->>R: 解析（json 过 schema）、跑 checks
    alt 通过
      R->>DB: 事务：写 artifact、edge、llm_call
    else 不通过
      R->>R: 用户消息末尾追加「上次输出的问题：……请重写」
    end
  end
  R-->>SC: 成功：产物；失败：节点 failed，问题列表显示给用户
```

- 重写次数 2 是拍的，M0 看失败率再定。
- 8k token 的报警线是拍的（定妆照实验每次读入约 5.3k），只算我们发出的系统提示词和用户消息；模型网关自己附加的部分不算（七牛实测：只发一句话时计费输入约 4.2k token）。
- 每次调用都记 `llm_call`：完整的 system、user、输出、token、耗时，用于复查和盲审。
- **修改模式**：带 `previous` 和 `instruction` 时，用户消息末尾加两段：「上一版」（上一版输出原文）和「创作者的修改意见」。系统提示词不变。

### 用户消息格式

按上下文清单的顺序，每段一个中文标题：

```text
【人物卡】
沈照雪：女，看起来二十四岁，青冥宗宗主，女主；本集要手持宗主令、被押上石台；冷而倔。

【剧本里写到她外貌的原句】
……

【同集其他人物】
厉寒山：主色玄黑，宽肩，束发冠……
```

清单里没有的东西不放。清单为空的段不出现。

| 裁头尾 | `trim.md` | 无 | 片段抽帧、段时长、是否承接 | json：`in`、`out` | 见 08 |
| 对话助手 | `assistant.md` | 无 | 见 09 | json | 见 09 |

提示词文件都在 `config/prompts/tasks/` 下。

「此刻状态」由程序从剧本推出：每一拍写了哪些东西变了（受伤、出鞘、锁链断），段时间轴和关键帧描述拿到的是到这一刻为止的累计状态。

## 三、提示词文件与组装

所有提示词用中文写：系统提示词、用户消息，以及交给 GPT Image 和 H3 的提示词。系统提示词统一三段：「你是什么」「你要干什么」「输出是什么」。

### 提示词是代码配置

系统提示词和固定句都是代码仓库里的配置文件，随代码一起做版本管理；改提示词就是改配置文件。文件里只有发给模型的正文，没有注释和出处。

```text
config/
  prompts/
    tasks/<任务>.md                每个任务一份系统提示词，通用
    image-types/<图类>.md          每类图的固定部分：背景、构图、光
  plugins/
    style/<画风>/                  画风插件
      plugin.json
      writer.md                    插进写手提示词的画风要求
      image/<对象>.md              插进出图提示词开头的画风句：人物、道具、场景、关键帧各一句，plugin.json 的 imagePrefix 写每类图用哪一句
      style-ref.png                风格参考图：没有人、没有字的场景，绑给场景主图、换机位图和关键帧
    genre/<题材>/                  题材插件
      plugin.json
      character.md、prop.md、describe.md
      story.md、dialogue.md、sample.md   本集设定和剧本用：题材的戏怎么写、台词口吻、一段原著口吻范例
      location.md                  地点外观设计用：形制、材质、尺度、天地景象
```

图类：`portrait`（定妆照）、`turnaround`（三视图）、`face`（脸部特写）、`prop-sheet`（道具设定图）、`location`（场景主图）、`location-view`（换机位图）、`keyframe`（关键帧）、`outfit`（服装平铺）。定妆照、三视图、脸部特写用人物句，道具设定图和服装平铺用道具句，场景主图、换机位图用场景句，关键帧用关键帧句。

### 组装

任务提示词里用占位符引用插件片段：

| 占位符 | 换成 |
|---|---|
| `{{style.name}}`、`{{genre.name}}` | 画风、题材插件 `plugin.json` 里的 `name` |
| `{{style:writer}}`、`{{style:character}}` | 画风插件 `fragments` 里对应文件全文 |
| `{{genre:character}}`、`{{genre:prop}}`、`{{genre:describe}}`、`{{genre:story}}`、`{{genre:dialogue}}`、`{{genre:sample}}`、`{{genre:location}}` | 题材插件 `fragments` 里对应文件全文 |

规则：

1. 组装后文本里还剩 `{{` 就报错，不发请求。
2. 引用的片段在插件里没有声明、或声明的文件不存在，就报错。题材插件某个片段确实没有要求时，放一个空文件，以区分「忘了写」。
3. `prompt_version` = 组装后系统提示词全文的 sha256 前 16 位，随每次调用和产物记录。

### 插件

画风和题材以插件提供，为以后扩展留空间。第一版只内置一个画风插件 `3d-guoman`（3D 国漫）和一个题材插件 `xianxia`（仙侠），立项时直接使用，不提供选择。

- `plugins.ts` 启动时扫描 `config/plugins/`，读每个 `plugin.json`：声明了的文件只要有一个不存在，整个插件就不加载，并写明缺了什么。
- 插件可以暂时不声明某项能力（例如还没做风格参考图）；用到这项能力时（出图要画风句和风格参考图）再检查，没有就报错。这样文本任务能先跑起来，出图的部分在 M1 补齐。
- 画风插件的片段：`writer`（所有描写任务都用的画风要求）、`character`（只有人物相关任务用：美型档次、肤质）。题材插件的片段：`character`、`prop`、`describe`，以及 `story`（这个题材的戏靠什么成立）、`dialogue`（台词口吻）、`sample`（一段原著口吻范例，注明只学口吻）、`location`（地点的形制、材质、尺度和天地景象）。
- 项目表里记 `style`、`genre` 两个插件 id。
- 以后加一个画风或题材，就是新增一个插件目录；立项页在有多个插件时再加选择。

## 四、出图提示词的拼装

模型只写主体段，其余由程序按固定顺序拼：

```text
1. 画风句        画风插件 image/<图类>.md
2. 参考图说明    程序生成：「参考图 1 是沈照雪的定妆照，参考图 2 是石殿主图……」
3. 主体段        模型写的描述（定妆描述、场景描述、关键帧描述等）
4. 固定部分      config/prompts/image-types/<图类>.md：背景、构图、光
```

各图类的组成：

| 图类 | 画风句 | 参考图 | 主体段 | 固定部分 |
|---|---|---|---|---|
| 定妆照 | 有 | 无 | 定妆描述 | 浅灰纯色背景、柔和均匀光、全身、中性站姿、颈部挺直 |
| 三视图 | 有 | 定妆照 | 无，「同一个人、同一套衣服，正面、侧面、背面」写在固定部分里 | 三个全身等高、正交、浅灰底、无文字 |
| 造型定妆照 | 有 | 开场那套的定妆照 | 程序加一句「换上另一套造型：脸、五官、身形和身高照定妆照，发型和衣服照描述」（`config/prompts/costume.md`），再接这套的定妆描述 | 同定妆照 |
| 脸部特写 | 有 | 定妆照 | 无，「同一张脸，正面头肩」写在固定部分里 | 浅灰底、柔和光 |
| 服装平铺 | 道具句 | 定妆照 | 无，「整套衣服正面背面平铺、没有人」写在固定部分里 | 浅灰底、正面平光、无投影、无文字 |
| 道具设定图 | 有 | 无 | 道具描述 | 正面、侧面、背面三视图并排，浅灰底、正面平光、无投影、正交、一处细节放大 |
| 场景主图 | 有 | 风格参考图；场内关键道具的设定图 | 场景描述 | 不画人、开场状态、框入整个场景 |
| 换机位图 | 有 | 地点主图；风格参考图 | 换机位描述 | 不画人 |
| 关键帧 | 有 | 图 1 始终是这个机位的空房间（主视角用主图，其余用换机位图），其后是人物、关键道具、风格参考图。近景也不改上一张已经有人的关键帧 | 关键帧描述 | 房间以图 1 为准，可以更近，不重画桌子；只画正文里写到的手；不补图上没有的字 |

拼装在 `src/compose.ts` 的 `imagePrompt`：四部分之间空一行，空的部分跳过；参考图说明写成「图 1 是……。图 2 是……。」，和关键帧描述里的编号一致。

**越界词检查**：模型写的主体段里出现画风、背景、构图、机位、光照这几类词（词表在 `compose/boundary.ts`），就让模型重写这一段，计入任务卡的重写次数。关键帧描述允许写人物受光方向，词表按图类区分。

**参考图数量**：GPT Image 的上限按 Yir 接口返回的合同读取，超出时按「起始帧、主要动作人物、关键道具、地点、其余人物」的顺序保留。

## 五、视频提示词的编译

视频提示词完全由程序编译，不经模型。H3 官方格式分六段，按顺序：

| 段 | 内容来源 |
|---|---|
| 主体定义 | 每张参考图的编号、指代和这张图的锚点：「<Picture 1> 是韩立，穿青布衣，锚点：方脸、头顶单髻、腰间葫芦」；「<Audio 1> 是韩立的声音」。锚点取外观要点的「锚点：」行，其余外观不写 |
| 概要 | 分段计划里这一段的一句话 |
| 保留 | 逐张图写它负责什么、保留到什么程度，不写笼统的「全部保持不变」：关键帧负责这一切开场的构图、站位和姿态；定妆照只负责脸、发型、身形和这套造型，不负责构图、动作和表情，也不继承定妆照的正面居中和直视镜头；地点视图只负责空间和陈设方位；道具设定图只负责形状和结构，不负责在谁手里、什么状态；服装平铺只负责这几个人的衣服、鞋和佩物，不负责脸、发型和身形。此刻和参考图不一样的状态（受伤、出鞘、衣服破损）写明以正文为准 |
| 详细描述 | 时间轴正文，每个镜头一条，写成「第 a–b 秒：……」（2026-10-28 前的逐秒时间轴仍写「第 N 秒」），切点处标「第 N 切」。表演只写看得见的身体变化，幅度宁小勿大 |
| 声音 | 台词时间线（谁、首字到末字、说什么、说完闭嘴）和底声。台词期间画面里看得到其他人的正脸时，写明他们不说话、嘴唇闭合；画外音写明说话人嘴唇闭合 |
| 配乐 | 固定为「无」 |

六段的中文名称和写法以 H3 官方文档为准，M1 前对一遍；M1 同时测中文与英文的效果。

保留段、旁人闭嘴和表演幅度三条来自 zenstory drama-skills 的 H3 写法（`skills/short-drama-video-prompts/references/minimax-h3.md`）和 waoowaoo 的视频导演规范，还没有在我们的 H3 上实测；M1 出片时按「一次只改一个变量」各测一次：旁人闭嘴用「远处一人说话、近处一人正对镜头不说话」的镜头，看口型落在谁脸上。

## 六、提示词怎么写

1. 统一三段：你是什么 → 你要干什么 → 输出是什么。
2. 「你要干什么」按模型写作的顺序组织：写什么、为什么要写全 → 按画面从整体到局部列出要写详细的地方 → 写法 → 不写什么。
3. 一个任务只放它用得到的要求；只适用于某个画风或题材的，写进对应插件的片段，任务提示词里只放通用的。
4. 同一个要求全篇只说一次；保留短例子（「过道两侧各三条」「无刘海」）帮模型把握程度。
5. 每份约 1500 字以内（拍的，M0 后校正）。
6. 方位只用画面的上下左右，不用东南西北（创作者 2026-10-28）。输出会写到方位的任务提示词都写明，写在管位置的那条要求里；故事方向、切集、拆剧本、审剧本写不到方位，不加：按各任务写的东西说：场景主图描述用主图画面的方位；定妆照、道具图用这张图的方位；时间轴用这个镜头自己画面的方位，站位里主图的左右按相机朝向换算；换机位图只写相机在主图画面的哪一边，关键帧只写人在这一帧画面的上下左右，都不再把外观要点换算成一套新的房间（创作者 2026-10-28）；机位归并、换机位图写相机站位时按主图画面说；剧本和地点外观设计在主图之前写，以进门看进去的视角为准；照抄的台词、「[变化]」和地名原样保留。站位另有程序检查，写了东南西北就打回。

旧项目和 manju 中有用的经验已经写进这些提示词和流程设计；审核过程稿在 `docs/归档/经验审核/`，只作历史记录。
