## M0：写手定型（只调文本模型，不花生成费）

1. 模型配置：`config/models.json` 和钥匙串读取；M0 阶段先用配置文件配好一个文本模型，设置页到 M2 再做。
2. 补齐 `config/` 下的配置文件：
   - `prompts/tasks/`：故事方向、剧本、人物外观设计（已有）、地点外观设计、道具外观设计、定妆描述（已有）、场景描述、道具描述、换机位描述、分段、段时间轴、关键帧描述、裁头尾、对话助手。
   - `prompts/image-types/`：定妆照、三视图、脸部特写、道具设定图、场景主图、换机位图、关键帧的固定部分。
   - 画风插件 `3d-guoman`：writer（已有）、各图类画风句、风格参考图。
   - 题材插件 `xianxia`：character、prop、describe（已有）。
3. 搭最小骨架：插件加载、提示词组装、模型调用、任务卡执行（校验与重写）、文本链路脚本 `src/m0/chain.ts`。产物库在 M1 前补：M0 的上下文由链路脚本按上下文清单直接组装，结果写在 `runs/` 下。

4. 每类任务用固定输入跑 3 次，看同一输入下哪些维度在变；会影响剧情的维度（例如刀的长短决定能否藏进袖子）补进外观要点，其余交给钉死机制。

验收：创作者盲审每类输出，认可写得够详细。

## M1：一段样片（花少量生成费）

输入是一段手写剧本，规格如下（数字是拍的，按内容微调）：

- 45–60 秒，约 4–6 段；3 个人物，至少两人有对手戏；2 个地点，中间一次转场；3–4 件道具，至少一件被拿起、交出或损坏；6–8 句台词，有一处两人来回对话；至少一段打斗或追逐和一段文戏；1–2 处特效；3 处以上状态变化，变化前后都出现在画面里。

实现：出图与视频执行器、GPU 连接、裁头尾、拼接与字幕、★4–★9 的审核页（可以先做简单版）。

走完：外观设计 → 定妆描述 → 出图锁定 → 试音 → 分段 → 时间轴 → 关键帧 → 逐段 576p 草稿 → 拼草稿 → 精修 → 交付片。

顺带测（同一输入、两颗种子、一次只改一个变量）：

- 只绑图时，GPT Image 和 H3 能否保住参考图细节。
- 打戏和特效在钉帧下切点准不准、动作清不清楚。
- 状态变化前后的画面是否对得上。
- 同一参考音频跨段是否像同一个人；台词口型。
- 中文与英文视频提示词在 H3 上的效果对比，差再改。
- 反应镜写法：触发后用一个情绪词点明，再给两处可见反应，1.5 秒内完成。
- 一段里快切几个镜头角色还稳。
- 裁头尾的允许范围、字幕时间校准。
- 精修带精修片尾巴时，接缝是否顺；精修片和采用的草稿相比动作走样多不多。

验收：创作者认为样片能看；每一处失败都能说出是哪一步、哪个输入造成的。

## M2：一句话到一集

加上立项、故事方向、本集设定、本集剧本（正文和拆拍）与出场清单、整集分段、九个审核点的完整界面、对话助手。地点外观设计在引擎里也要读到本集设定和各场环境段（M0 链路 `src/m0/chain.ts` 已经这样组装，`src/pipeline/entities.ts` 的 `brief` 节点到 M2 接上）。

验收：从一句话出发，创作者只在九个审核点操作，得到一集交付片。

## M3：小说到第 1 集

加上导入、拆章、章节摘要、分集卡；用一部真实的连载小说做样本。外观设计要能读到全书里对这个人物的外貌描写（散在前面各章）。

验收：创作者认可分集卡；第 1 集成片通过。

## M4：第 2 集

加上资产复用（直接引用第 1 集已锁定的人物、地点、道具、音色）和集末交接卡（谁受了伤、谁知道了什么、东西在谁手里、留下什么悬念，创作者确认后作为第 2 集剧本的上下文）。伏笔管理、跨集推理、季规划不在第一版。

验收：第 2 集不重新设计已出场的人物，人物在两集里是同一个人。
